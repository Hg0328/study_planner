## 2. 작업별 정리

### 2-1. 저장소 정리 (#1)
- 시작 시점 저장소는 웹 업로드본 그대로였고, 점 파일 3개가 없었음 → 사용자가 준 원본 내용으로 복원.
- 첫 푸시는 GitHub 권한(403)으로 실패 → 사용자가 연결을 고친 뒤 성공.

### 2-2. 단위 테스트 + 날짜 버그 (#2)
- `test/scheduler.test.js`(겹침·배정 비중·선호 요일·단계 순서·하루 한도), `test/scopeParser.test.js`(공지 형식·팁 제외·날짜·과목명).
- 실패한 테스트로 버그 발견: 오늘 `2027-01-03`에 "12월 20일" → `2027-12-20`으로 잘못 추정.
- 수정 규칙(사용자 지정): 작년·올해·내년 중 오늘 기준 **60일 전 ~ 305일 후** 범위의 연도, 없으면 올해.

### 2-3. 시험 조합 지원 (#3)
- **생활 유형**(계정): 중·고등학생 / 대학생 / 수험생·취준생 / 직장인 / 직접 설정 → 기본 시간표·문구("학교"↔"강의"↔"근무")·하루 최대 공부량.
- **시험 종류**(시험): 내신 / 수능·모의고사 / 대학 / 자격증·어학 / 공무원·취업 / 직접 설정 → 단계 이름·비율, 범위 단위, 추천 과목.
- **우선순위** 높음·보통·낮음 = ×1.5 / ×1 / ×0.6.
- **장기 시험 최소 비중**: 60일 이상 남은 시험에 하루 블록 20%(0~50%) 보장, D-3 이내 시험이 있는 날 해제.
- **28일 생성 + 이어 생성**: 끝까지 시뮬레이션해 단계 비율·`exams.expected_min`(진행률 분모)을 계산하고 28일치만 저장. 진도는 `plan_from`부터 셈.
- 기존 계정은 첫 접속 때 28일치로 다시 생성(`needsRegen`).
- **버그 수정**: 빈 선호 요일이 `'0'`(일요일)로 저장되던 문제 → 저장 수정 + 기존 데이터 정리는 `meta` 기록으로 **한 번만** 실행(일요일만 고른 기존 시험도 초기화됨, 사용자 승인).
- 성능: 1년치·과목 30개 시뮬레이션 약 15~24ms(작업 환경 측정).

### 2-4. 시험별 진행률 (#4)
- 제목 "과목별" → "시험별", 종류가 2개 이상이면 종류 소제목으로 묶음, 직접 설정은 "기타 시험"/"· 기타", 가까운 순, 줄마다 D-Day.

### 2-5. 기본 모드 (#5)
- `settings.mode` = `basic`(간단하게 설정할래요) | `expert`(다 설정할래요), 기존 계정은 expert.
- `data-expert`(기본 모드에서 숨김) / `data-basic`(기본 모드에서만 보임) 속성 방식.
- 단계형 설정: ① 시험 ② 학교 시간 ③ 학원 ④ 식사 ⑤ 생활 유형 → 완료 시 계획 생성.
- `GET /api/week` 추가(하루 API와 같은 형태 × 7).
- 확인: main 코드와 픽셀 비교로 기존 계정 화면이 같음을 확인.

### 2-6. 플래너 보기 통합 · 백색소음 (#6)
- `week.html` 삭제 → `planner.html?date=…&view=day|week`. 전문가는 탭 2개 + 마지막 보기 저장(`plannerView`), 기본 모드는 일주일 보기만.
- 전문가 일주일 보기: 과목별 이번 주 계획·완료 시간, A4 가로 인쇄(하루는 A4 세로).
- **주 시작 요일을 월요일 → 일요일**로 변경(사용자 요청, 달력 줄과 같음). 토요일 미루기 → 다음 주 일요일.
- 백색소음: 기본 잡음(선명↔부드럽게)·빗소리(가랑비↔소나기)·파도·장작불·시냇물·바람, 3초 미리듣기, 크로스페이드, 예전 white/pink/brown 값 변환. 설계 값은 `noise.js`의 `NOISE` 상수.
- 계획 스냅샷 테스트 추가(설정을 안 건드리면 계획이 main과 같은지).

### 2-7. 고급 설정 · 단계 올리기 · 문구 (#7)
- **고급 탭 6개**: 이동 시간 가기 전/끝난 뒤, 쉬는 시간, 단계 비율, 마지막 복습 블록, 요일별 기상·취침, 과목별 하루 최대 블록 + 「기본값으로 되돌리기」. 기본값이면 계획 결과 동일.
- **제외**: 시험 직전 가중치(D-1 ×4, D-2 ×1.6) — 사용자 결정.
- **단계 올리기**: 하루 상한 = `min(최대, 시작값 + 블록 × floor(지난 날 ÷ 주기))`.

  | 단계 | 시작값 | 폭·주기 |
  |---|---|---|
  | 천천히 | 최대의 50% | 3일마다 블록 1개 |
  | 보통 | 최대의 50% | 2일마다 블록 1개 |
  | 빠르게 | 블록 1개 | 매일 블록 1개 |

  시작일 `users.ramp_start`, 시험 7일 안이면 해제, 두 모드 모두 선택 가능.
- **문구**: 「하루 보기 ›」→「하루 계획 보기 ›」, 「🗓 일주일 보기」→「🗓 일주일 계획 보기」, 탭은 유지.
